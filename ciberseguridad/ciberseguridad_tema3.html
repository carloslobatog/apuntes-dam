Sistema DNS

El Sistema de Nombres de Dominio (DNS) es la infraestructura que permite a Internet funcionar de manera intuitiva para los humanos. Esencialmente, actúa como la guía telefónica de Internet, traduciendo los nombres de dominio fáciles de recordar (como google.com) a las direcciones IP numéricas (como 142.250.67.14) que las máquinas utilizan para comunicarse.

Nombres de Dominio

Un nombre de dominio es una dirección legible por humanos que se utiliza para identificar un sitio web en Internet. Está compuesto por varias partes, separadas por puntos, y cada parte tiene un significado específico. Por ejemplo, en el nombre de dominio "www.ejemplo.com", "www" es un subdominio, "ejemplo" es el nombre del dominio, y "com" es el dominio de nivel superior (TLD).

Los nombres de dominio pueden estar formados por una o más cadenas de caracteres separadas por puntos y no se distingue entre mayúsculas y minúsculas. Por ejemplo, www.google.es que WWW.GooGle.ES

Dominio raíz

Los dominios raíz son los niveles más altos en la jerarquía de nombres de dominio. El único dominio raíz es ".", que representa la raíz del árbol de nombres de dominio. En la práctica, los dominios raíz no se utilizan directamente, sino que se utilizan los dominios de nivel superior (TLD) como ".com", ".org", ".net", etc.

Un dominio se lee de derecha a izquierda, empezando por el punto ., aunque en la práctica lo hacemos de izquierda a derecha. El punto inicial, generalmente se omite ya que los programas lo añaden por defecto y es meramente formal, pero en ocasiones, será necesario que indiquemos el nombre de dominio completo incluyendo el dominio raíz, es lo que se conoce como nombres de dominio completos (Fully Qualified Domain Names, FQDN).

Durante una consulta DNS sin caché, cada vez que un usuario introduce una dirección web en su navegador, esta acción desencadena una búsqueda DNS, y todas las búsquedas DNS comienzan en la zona raíz Una vez que la búsqueda llega a la zona raíz, la búsqueda bajará en la jerarquía del sistema DNS, alcanzando primero los servidores de TLD, luego los servidores para dominios específicos (y posiblemente los subdominios), hasta que acabe llegando al servidor de nombres autoritativo para el dominio correcto, que contiene la dirección IP numérica del sitio web que se está buscando. Esta dirección IP se devuelve entonces al cliente. Es interesante que, a pesar del número de pasos necesarios, este proceso puede ocurrir muy rápido. Los servidores raíz son una parte fundamental de la infraestructura de Internet; sin estos no funcionarían ni los navegadores web ni muchas otras herramientas de Internet. Hay 13 direcciones IP diferentes que sirven a la zona raíz de DNS, y existen cientos de servidores raíz redundantes en todo el mundo para gestionar las solicitudes a la zona raíz.

El mito de las 13 direcciones raíz.

Es un mito común que solo hay 13 servidores raíz de DNS en todo el mundo. En realidad, hay 13 direcciones IP diferentes que representan a los servidores raíz, pero cada una de estas direcciones IP puede estar respaldada por múltiples servidores físicos distribuidos globalmente. Esto significa que, aunque solo haya 13 direcciones IP, hay muchos más servidores raíz en funcionamiento para garantizar la redundancia y la disponibilidad. El número 13 no fue un capricho administrativo, sino una limitación matemática. En los inicios del DNS, el tamaño máximo de un paquete de datos UDP para garantizar que no se fragmentara en la red era de 512 bytes. Tras acomodar la estructura básica del protocolo, el espacio sobrante solo permitía listar exactamente 13 direcciones IPv4. Hoy en día, esas 13 direcciones IP actúan como "máscaras". Cuando tu red hace una consulta a una de ellas, los routers no te envían a una única máquina central, sino a la copia física de ese servidor que geográficamente esté más cerca de ti. Esto hace que el sistema sea increíblemente rápido y resistente a ataques.

Hoy en día existen más de 1,700 instancias físicas de estos servidores raíz repartidas por todo el planeta. Si alguna vez tienes curiosidad, entidades como root-servers.org mantienen un mapa en tiempo real con la ubicación exacta de cada uno de ellos.

Resource Records

Los registros de recursos (Resource Records, RR) son la unidad básica de información en el sistema DNS. Cada registro de recursos contiene información sobre un dominio específico y su correspondiente dirección IP u otros datos relacionados. Los registros de recursos se almacenan en los servidores DNS y se utilizan para responder a las consultas de los clientes.

Cada RR es una línea de datos que contiene información sobre el dominio, como su dirección IP, los servidores de correo, los servidores autoritativos, etc. Existen varios tipos de registros de recursos, cada uno con un propósito específico.

En el contexto de DNS, un RR sigue una estructura básica:

Nombre TTL Clase Tipo Datos
  • Nombre: El nombre del dominio al que se refiere el registro.
  • TTL: El tiempo de vida del registro, indicando cuánto tiempo debe ser cacheado.
  • Clase: La clase de red a la que pertenece el registro (generalmente IN para Internet).
  • Tipo: El tipo de registro (A, AAAA, CNAME, MX, etc.).
  • Datos: La información específica asociada al tipo de registro.

Algunos de los tipos de registros más comunes incluyen:

Tipo RR Descripción
A Asocia un nombre de dominio con una dirección IPv4.
AAAA Asocia un nombre de dominio con una dirección IPv6.
CNAME Alias de un nombre de dominio a otro nombre de dominio.
MX Especifica los servidores de correo para el dominio.
NS Indica los servidores de nombres autoritativos para el dominio.
TXT Permite almacenar texto arbitrario, a menudo usado para verificación y políticas.
SOA Contiene información sobre el servidor de nombres autoritativo para el dominio.

Tendremos algunas herramientas para consultar registros DNS:

  • nslookup: Herramienta de línea de comandos para consultar registros DNS.
  • dig: Herramienta más avanzada para realizar consultas DNS detalladas.
  • host: Herramienta simple para obtener información de direcciones IP y registros DNS.

Consultas DNS

Una consulta DNS es el proceso mediante el cual un cliente (como un navegador web) solicita información sobre un nombre de dominio a un servidor DNS. Este proceso es esencial para traducir nombres de dominio legibles por humanos en direcciones IP que las computadoras pueden entender y utilizar para establecer conexiones.

Vamos a estudiar los diferentes tipos de consultas DNS y cómo se utilizan en la práctica. Para ello, tenemos que estudiar algunos conceptos clave:

  • Resolutor DNS (DNS Resolver): Es el cliente que realiza las consultas DNS y gestiona la resolución de nombres.
  • Servidor DNS recursivo: Es el servidor que responde a las consultas DNS, proporcionando la información solicitada.
  • Servidor Raíz (root server): Es el servidor DNS más alto en la jerarquía, que responde a las consultas sobre dominios de primer nivel. Es el punto de partida de la búsqueda.
  • Servidor TLD (Top-Level-Domain): Es el servidor que gestiona los dominios de primer nivel (como .com, .org, .net).
  • Servidor DNS autoritativo: Es el servidor que tiene la autoridad sobre un dominio específico y proporciona respuestas definitivas a las consultas. Es decir, devuelve la IP final.

Consultas recursivas e iterativas

Consulta recursiva

Una consulta recursiva es aquella en la que el servidor DNS da una respuesta completa o exacta. Pueden darse tres tipos de respuesta:

  • Positivas: se devuelve información sobre el dominio consultado
  • Negativas: no se puede resolver el nombre de dominio.
  • Error: se produce un fallo en la red.

Consulta iterativa

Una consulta iterativa es aquella en la que el servidor DNS proporciona una respuesta parcial. Existen cuatro posibles respuestas:

  • Positivas: se devuelve información sobre el dominio consultado
  • Negativas: no se puede resolver el nombre de dominio.
  • Referencia: el servidor DNS indica a otros servidores a los que se les puede sonsultar para
  • Error: se produce un fallo en la red.
