1. Software y Programa. Tipos de Software

El software es el conjunto de programas informáticos que actúan sobre el hardware para ejecutar lo que el usuario desee. Según su función, se distinguen tres tipos:

  • Sistema Operativo: Es el software base que ha de estar instalado y configurado para que las aplicaciones puedan ejecutarse.
  • Software de Programación: Herramientas que permiten desarrollar programas informáticos.
  • Aplicaciones: Conjunto de programas que tienen una finalidad concreta.

A través de un lenguaje de programación se realiza la escritura de un programa, y está formado por conjunto de símbolos y palabras reservadas que permitirán al programador aportar instrucciones a un ordenador para que sean ejecutadas. ​ ​ El primer paso a realizar, por tanto, es escribir el programa en un lenguaje de programación. Una vez realizado, el programa escrito se va a traducir al lenguaje máquina. Este proceso es al que se conoce como compilación. Cada lenguaje de programación tiene su propio compilador (excepto los lenguajes interpretados).​

En programación podemos trabajar con distintos tipos de traducción: compilación y ejecución directa.

Lenguajes interpretados

Los lenguajes interpretados son aquellos que no necesitan un proceso de compilación previo para su ejecución. En su lugar, el código fuente se ejecuta directamente mediante un intérprete, que traduce y ejecuta las instrucciones línea por línea en tiempo real. Esto permite una mayor flexibilidad y facilidad de depuración, aunque puede resultar en un rendimiento más lento en comparación con los lenguajes compilados.

Algunos ejemplos de lenguajes interpretados son Python, JavaScript y Ruby.

Figura 1: Lenguajes interpretados: Python, JavaScript y Ruby

En la figura 1 se muestran ejemplos representativos de lenguajes interpretados. Python, JavaScript y Ruby se ejecutan mediante un intérprete, sin necesidad de compilar el código antes de cada ejecución. Esto facilita el desarrollo y la depuración, aunque suele implicar un rendimiento inferior al de los lenguajes compilados.

Lenguajes compilados

Los lenguajes compilados requieren un proceso de compilación previo, donde el código fuente se traduce a código máquina antes de su ejecución. Este proceso genera un archivo ejecutable que puede ser ejecutado directamente por el sistema operativo. Los lenguajes compilados suelen ofrecer un mejor rendimiento y eficiencia, pero requieren un paso adicional de compilación antes de poder ejecutar el programa.

Figura 2: Diagrama de flujo del proceso de compilación

La figura 2 representa la secuencia del proceso de compilación. El código origen es analizado por el compilador, que genera un programa objeto; después, el enlazador incorpora las librerías necesarias y produce el programa ejecutable. También se muestran los errores que pueden aparecer en estas etapas.


Programa fuente:

Programa escrito en un lenguaje de alto nivel (texto ordinario que contiene las sentencias del programa en un lenguaje de programación). Necesita ser traducido a código máquina para poder ser ejecutado.​

Compilador:

Programa que traduce el código fuente a código objeto. Puede generar errores de compilación si el código fuente contiene errores de sintaxis o semántica.​

Programa objeto:

Código binario intermedio que resulta de compilar el código fuente. Puede contener referencias a librerías externas que deben ser resueltas por el enlazador.​

Enlazador:

Programa que combina el código objeto con las librerías necesarias para generar un programa ejecutable. Puede generar errores de enlace si faltan librerías o símbolos no resueltos.​

Librerías:

Conjunto de funciones y rutinas precompiladas que pueden ser utilizadas por el programa objeto. Facilitan la reutilización de código y la modularidad del software.​

Programa ejecutable:

Código binario final que puede ser ejecutado directamente por el ordenador. Contiene todas las instrucciones necesarias para que el programa funcione correctamente.​

2. Tipos de lenguajes de programación

Figura 3: Clasificación de los lenguajes de programación

La figura 3 organiza los lenguajes según dos criterios principales: por niveles y por paradigma. En el primer caso aparecen el lenguaje máquina, el de bajo nivel y el de alto nivel; en el segundo, se distinguen la programación imperativa y la declarativa, incluyendo dentro de la imperativa la programación estructurada y la orientada a objetos (POO).

Clasificación de los Lenguajes de Programación

Por niveles:
  • Lenguaje máquina: Es el único que entiende el ordenador. Sus instrucciones son unos y ceros.
  • Lenguaje de programación de bajo nivel: Se asemeja al lenguaje máquina, pero utiliza mnemotécnicos en lugar de unos y ceros. Necesita traducción al lenguaje máquina.
  • Lenguaje de programación de alto nivel: Utiliza sentencias cercanas al idioma inglés y al razonamiento humano.
Por paradigma de programación:
  • Programación Imperativa: Se basa en la ejecución de instrucciones que modifican el estado del programa.
    • La programación orientada a objetos (POO): Se basa en la creación de objetos que contienen datos y métodos para manipular esos datos.
    • La programación estructurada: Se basa en la utilización de estructuras de control como bucles y condicionales para organizar el flujo del programa.
  • Programación Declarativa: Se centra en la descripción de lo que se quiere lograr, sin especificar cómo hacerlo.

Programación imperativa

La programación imperativa es un paradigma de programación que se centra en describir cómo se debe realizar una tarea mediante una secuencia de instrucciones que modifican el estado del programa. En este enfoque, el programador especifica paso a paso las acciones que el ordenador debe ejecutar para lograr un resultado deseado. La programación imperativa se basa en la manipulación directa de variables y estructuras de datos, y utiliza estructuras de control como bucles y condicionales para controlar el flujo del programa.

La mayor parte del código que escribiremos este año seguirá el paradigma de programación imperativa, ya que es el más común y ampliamente utilizado en la mayoría de los lenguajes de programación. Este enfoque permite a los programadores tener un control detallado sobre el flujo de ejecución y la manipulación de datos, lo que facilita la creación de programas eficientes y funcionales. Ejemplos de este paradigma incluyen lenguajes como C, C++, Java y Python, entre otros. La programación imperativa es especialmente útil para tareas que requieren un control preciso sobre el estado del programa y la ejecución de instrucciones en un orden específico.

Programación estructurada

La programación estructurada es un paradigma de programación que promueve la utilización de estructuras de control como bucles y condicionales para organizar el flujo del programa. Este enfoque facilita la comprensión, el mantenimiento y la depuración del código, ya que se evita el uso excesivo de saltos incondicionales (como el comando "goto") y se fomenta la modularidad y la claridad en la lógica del programa. Por ejemplo, en la programación estructurada se utilizan funciones o procedimientos para dividir el código en bloques lógicos, lo que permite una mejor organización y reutilización del código. Este paradigma es ampliamente utilizado en lenguajes de programación como C, Pascal y Ada. Los scripts de programación estructurada suelen seguir un flujo de control lineal y secuencial, lo que facilita la comprensión del programa y reduce la probabilidad de errores. Además, la programación estructurada fomenta la legibilidad del código, lo que es esencial para el trabajo en equipo y el mantenimiento a largo plazo de los proyectos de software.

Ejemplo de programación estructurada: 
          
            #include <stdio.h>

            void imprimirTablaMultiplicar(int numero) {
                for (int i = 1; i <= 10; i++) {
                    printf("%d x %d = %d\n", numero, i, numero * i);
                }
            }

            int main() {
                int numero;
                printf("Ingrese un número: ");
                scanf("%d", &numero);
                imprimirTablaMultiplicar(numero);
                return 0;
            }

En este ejemplo, se define una función llamada imprimirTablaMultiplicar que toma un número como parámetro y utiliza un bucle for para imprimir la tabla de multiplicar de ese número. La función main solicita al usuario que ingrese un número y luego llama a la función para mostrar la tabla correspondiente.

Programación orientada a objetos (POO)

La programación orientada a objetos (POO) es un paradigma de programación que se basa en la creación de objetos, los cuales encapsulan datos y métodos para manipular esos datos. Este enfoque permite modelar el mundo real de manera más intuitiva, facilitando la reutilización de código, la modularidad y la organización del software. Los conceptos 4 pilares básicos de la POO son: abstracción, herencia, polimorfismo y encapsulamiento.

Cuando creamos un objeto en POO, estamos creando una instancia de una clase. Esto se hace con el método constructor asociado a la clase. Cada objeto tiene sus propios valores para los atributos y puede ejecutar los métodos definidos en su clase. Por ejemplo, si tenemos una clase "Coche" con atributos como "color" y "marca", podemos crear varios objetos de la clase "Coche", cada uno con su propio color y marca. Además, podemos definir métodos como "arrancar()" y "frenar()" que los objetos pueden utilizar para realizar acciones específicas.

Los nombres de las clases van siempre en singular y se escriben en mayúscula la primera letra de cada palabra (CamelCase).

                
    public class Coche {
    private String color;
    private String marca;

    //Método constructor de la clase Coche
    public Coche(String color, String marca) {
      this.color = color;
      this.marca = marca;
    }

    public void arrancar() {
      System.out.println("El coche está arrancado.");
    }

    public void frenar() {
      System.out.println("El coche está frenando.");
    }
  }
                
              
          
      public class Main {
          public static void main(String[] args) {
              Coche miCoche = new Coche("Rojo", "Toyota");
              miCoche.arrancar();
              miCoche.frenar();
          }
        }

🧠 Abstracción:

Es la capacidad de ocultar detalles complejos y mostrar solo la información esencial. Por ejemplo, al crear una aplicación de música, no es necesario conocer los detalles internos del funcionamiento del reproductor para utilizarlo. Además, cuando pensemos en los atributos necesarios para una clase, escogeremos únicamente los necesarios para la aplicación.


🔒 Encapsulamiento:

Es la práctica de ocultar los detalles internos de un objeto y exponer solo lo necesario a través de métodos públicos. Por ejemplo, si tenemos una clase "CuentaBancaria" con un atributo "saldo", podemos encapsular ese atributo y proporcionar métodos públicos como "depositar()" y "retirar()" para interactuar con el saldo sin exponerlo directamente.

En Java utilizamos las palabras reservadas "private", "protected" y "public" para controlar el acceso a los atributos y métodos.

  • private: El atributo o método solo es accesible dentro de la misma clase.
  • protected: El atributo o método es accesible dentro de la misma clase y sus subclases.
  • public: El atributo o método es accesible desde cualquier lugar.

👨‍👩‍👧‍👦 Herencia:

Es la capacidad de crear nuevas clases basadas en clases existentes, heredando sus atributos y métodos. Por ejemplo, si tenemos una clase "Animal" con atributos como "nombre" y "edad", podemos crear una clase "Perro" que herede esos atributos y agregue un atributo adicional como "raza".

Recordemos que en Java se utiliza la palabra clave "extends" para indicar que una clase hereda de otra.


🐶🐱 Polimorfismo:

Es la capacidad de un objeto de tomar diferentes formas o comportamientos según el contexto. Por ejemplo, si tenemos una clase "Animal" con un método "hacerSonido()", podemos tener diferentes implementaciones de ese método en las clases "Perro" y "Gato", donde el perro ladra 🐶 y el gato maúlla 🐱.

Recordemos que en Java, utilizaremos la anotación @Override para indicar que un método está sobrescribiendo uno de la clase padre.

Programación declarativa

La programación declarativa es un paradigma de programación que se centra en describir qué se quiere lograr, en lugar de cómo hacerlo. En este enfoque, el programador especifica las propiedades del resultado deseado, y el sistema se encarga de encontrar la mejor forma de alcanzarlo. Este paradigma es especialmente útil para tareas que involucran lógica compleja o búsqueda de soluciones.

Ejemplos de lenguajes declarativos incluyen Dart (flutter) y SQL.

                            },

                      ),

                  ),
                );
              }

Desgranando el proceso de compilación

Recordemos que el proceso de compilación es un conjunto de pasos que transforman el código fuente escrito en un lenguaje de programación de alto nivel en un programa ejecutable que puede ser entendido y ejecutado por la computadora. Este proceso es esencial para garantizar que el código sea correcto, eficiente y funcional.

Figura 4: Fases del proceso de compilación

La figura 4 muestra el flujo interno del compilador. El programa fuente entra en una serie de fases sucesivas: análisis léxico, análisis sintáctico, análisis semántico, generación de código intermedio, optimización y, finalmente, generación del código objeto. La tabla de símbolos ayuda a registrar identificadores y datos, mientras que el manejador de errores detecta posibles fallos durante cada etapa.

El proceso de compilación consta de varias fases:

  • 1. Análisis léxico: El compilador lee el código fuente y lo divide en unidades léxicas llamadas tokens, que son secuencias de caracteres que representan palabras clave, identificadores, operadores y otros elementos del lenguaje.
  • 2. Análisis sintáctico: El compilador verifica la estructura del código fuente para asegurarse de que cumple con las reglas gramaticales del lenguaje de programación. Si se detectan errores de sintaxis, el compilador genera mensajes de error.

    Un ejemplo de fallo en el análisis sintáctico es la omisión de un punto y coma al final de una instrucción en lenguajes como C o Java. Otro ejemplo es la utilización incorrecta de paréntesis o llaves.

  • 3. Análisis semántico: El compilador verifica el significado del código fuente, asegurándose de que las operaciones y expresiones sean válidas y coherentes con el contexto del programa.

    Un ejemplo de fallo en el análisis semántico es la utilización de una variable sin haberla declarado previamente o asignar el valor de un tipo incompatible (como String a int).

  • 4. Generación de código intermedio: El compilador traduce el código fuente en un código intermedio que es más fácil de optimizar y analizar.
  • 5. Optimización de código: El compilador realiza mejoras en el código intermedio para aumentar la eficiencia y el rendimiento del programa final.
  • 6. Generación de código objeto: El compilador traduce el código intermedio optimizado en código objeto, que es un conjunto de instrucciones en lenguaje máquina que puede ser ejecutado por la computadora.

5. Fases en el Desarrollo y Ejecución del Software

A la hora de desarrollar software, es fundamental seguir un proceso estructurado que garantice la calidad y eficiencia del producto final. Existen diferentes modelos de ciclo de vida del software, como el modelo en cascada, el modelo iterativo, el modelo ágil y otros. Cada modelo tiene sus propias características y enfoques, pero todos comparten etapas esenciales que deben cumplirse para lograr un software confiable y funcional. Este caso particular es el modelo en cascada, que sigue un enfoque secuencial y lineal, donde cada fase debe completarse antes de pasar a la siguiente. A este tipo de metodología se le llama metodologías pesadas.Sin embargo, es importante destacar que otros modelos, como el ágil, permiten iteraciones y retroalimentación continua durante el desarrollo.

Independientemente del modelo de ciclo de vida elegido, hay etapas de obligado cumplimiento para construir software fiable:

  • 1. Análisis de Requisitos: Es la fase más importante. Se especifican los requisitos funcionales (qué hará el sistema) y no funcionales (tiempos de respuesta, legislación, etc.).
  • 2. Diseño: Se divide el sistema en partes, estableciendo relaciones y determinando la función de cada una.
  • 3. Codificación: Se elige un lenguaje de programación y se traduce la información a código fuente.
    • Código Fuente: Escrito por programadores, no es ejecutable por la máquina.
    • Código Objeto: Código binario intermedio que resulta de compilar el código fuente.
    • Código Ejecutable: Código binario que resulta de enlazar archivos objeto, y es inteligible por la computadora.
  • 4. Pruebas: Se prueba el software para asegurar su validación. Incluyen pruebas unitarias (partes por separado) y pruebas de integración (sistema completo).
  • 5. Documentación: Guardar y documentar toda la información para facilitar revisiones y el uso. Comprende la guía técnica, guía de uso y guía de instalación.
  • 6. Explotación: Es la instalación, configuración y funcionamiento de la aplicación en el equipo del cliente.
  • 7. Mantenimiento: Es la etapa más larga del ciclo de vida. Consiste en la mejora, optimización y actualización del software. Puede requerir cambios perfectivos, evolutivos, adaptativos o correctivos.
